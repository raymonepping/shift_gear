# Session and mutation contract (ADR)

Decision: retain a single BFF replica with bounded in-memory sessions. Pod replacement signs users out; there is no claim of shared-session availability. An opaque HttpOnly SameSite=Lax cookie identifies the session. Secure-cookie policy derives from the configured public callback URL, not caller-controlled forwarded headers. Entries have TTLs and are swept; capacity is bounded.

Vault mediates the OIDC exchange. The role now maps Keycloak `sub` to safe `oidc_subject` metadata. The BFF stores issuer and subject with the session. Backchannel logout validates a signed RS256 token with the trusted issuer's JWKS over project-CA-verified TLS, checks audience `vault`, event, issued time, subject and unique ID, rejects nonce/replay, and invalidates matching issuer+subject sessions. Subject-level logout intentionally clears all BFF sessions for that identity. SID-only messages cannot be matched by this deployment and are rejected. Initiating local logout still destroys the local session and attempts Vault revocation before the existing Keycloak end-session flow.

Replay tracking and session state share the single-instance lifetime: restart loses sessions and therefore cannot resurrect an old logged-out session. Signing-key rotation is bounded by the JWKS cache lifetime; malformed/unknown messages fail closed. Provider callback failures must never be used to grant a new session.

POST mutations require the configured application Origin. The backchannel endpoint is exempt from cookie-origin validation because its signed logout token is its authentication proof. Mutation/auth-entry request rates and tracking maps are bounded; forwarded client headers do not select the limiter identity. Direct forbidden requests are rejected independently of button visibility. The existing audit metadata readership remains all authenticated users, explicitly including viewer/staff; values are never exposed and access can be narrowed through a future owner decision.

Operator capability means `sg-operator` (or an explicitly privileged root session), not the approver label. Approvers do not implicitly receive administration privileges. The console never falls back to a bootstrap or root token. Denied/revoked Vault calls cannot produce a write acknowledgement. A transport timeout after a possible rotation is an uncertain write, not proof that nothing changed; the receipt remains accepted/unverified and must not automatically trigger a new operation.
